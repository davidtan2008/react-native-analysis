## 2. 【核心 JJJ-1】一份结构里的两套「未设置」表示

### 2.1 7 个 NaN 哨兵字段

```cpp
// packages/react-native/ReactCommon/react/renderer/attributedstring/TextAttributes.h:52-72
  // Color
  SharedColor foregroundColor{};
  SharedColor backgroundColor{};
  Float opacity{std::numeric_limits<Float>::quiet_NaN()};

  // Font
  std::string fontFamily{""};
  Float fontSize{std::numeric_limits<Float>::quiet_NaN()};
  Float fontSizeMultiplier{std::numeric_limits<Float>::quiet_NaN()};
  std::optional<FontWeight> fontWeight{};
  std::optional<FontStyle> fontStyle{};
  std::optional<FontVariant> fontVariant{};
  std::optional<std::string> fontVariationSettings{};
  std::optional<bool> allowFontScaling{};
  Float maxFontSizeMultiplier{std::numeric_limits<Float>::quiet_NaN()};
  std::optional<DynamicTypeRamp> dynamicTypeRamp{};
  Float letterSpacing{std::numeric_limits<Float>::quiet_NaN()};
  std::optional<TextTransform> textTransform{};
```

**实测统计**：

| 表示方式 | 字段数 | 字段 |
| --- | --- | --- |
| **`Float` + NaN 哨兵** | **7** | `opacity`、`fontSize`、`fontSizeMultiplier`、`maxFontSizeMultiplier`、`letterSpacing`、`lineHeight`、`textShadowRadius` |
| **`std::optional<T>`** | **19** | `fontWeight`、`fontStyle`、`fontVariant`、`fontVariationSettings`、`allowFontScaling`、`dynamicTypeRamp`、`textTransform`、`alignment`、`baseWritingDirection`、`lineBreakStrategy`、`lineBreakMode`、`textDecorationLineType`、`textDecorationStyle`、`textShadowOffset`、`isHighlighted`、`isPressable`、`layoutDirection`、`accessibilityRole`、`role` |
| **其他（自带空状态）** | 其余 | `SharedColor`（`{}` 即空）、`std::string`（`""`） |

### 2.2 两套表示的语义差异

| | `Float` + NaN | `std::optional<T>` |
| --- | --- | --- |
| 「未设置」的值 | `NaN` | `nullopt` |
| 「设置成了 NaN」 | **无法表达** | 无法表达（但语义上 `optional` 里装 NaN 是可表达的） |
| 「设置成了 0」 | ✅ 可表达 | ✅ 可表达 |
| 判空写法 | `std::isnan(x)` | `!x.has_value()` |
| 拷贝成本 | 4 字节 | **8–16 字节**（`optional` 有对齐/标志开销） |
| **在 `operator==` 里的判据** | **`floatEquality`（有 NaN 特判）** | `==` 直接比 `optional` |

**即：同一个结构体里，7 个字段和 19 个字段用**不同的机制**表达「未设置」，且在相等性判定里走**两条不同的代码路径**。

### 2.3 为什么 NaN 哨兵用在「数值」上

| 理由 | 说明 |
| --- | --- |
| **省内存** | `Float` + NaN = 4 字节；`optional<Float>` = 8 字节（对齐后） |
| **允许「继承默认样式」** | NaN 表示「本层不覆盖，交由上层/下层决定」—— `fontSize = NaN` 意味着「不设字号」 |
| **`defaultTextAttributes()` 能统一比较** | 默认值是具体数值（14.0 / 1.0），与 NaN 哨兵区分得开 |

**即：NaN 哨兵是一种「用特殊浮点值表达 absence」的紧凑编码** —— 与 52 文档 RR 类问题同源的「用值域的特殊子集表达额外状态」。

### 2.4 风险：NaN 哨兵与「用户真的传了 NaN」不可区分

**若 JS 侧传入 `fontSize: NaN`**（或经过计算产生 NaN），C++ 侧**无法区分**「用户设了 NaN」与「未设置」。

| 后果 | 说明 |
| --- | --- |
| **NaN 会传播到测量** | 53 文档实测：Yoga 的消毒**只拒 NaN 与负数**，`+inf` 直接放行 —— **NaN 本身是被拒的** ✓ |
| **但相等性判定会认为「NaN == NaN」** | 见 §3 —— **两个「未设置」与「一个未设置一个设成 NaN」无法区分** |

## 3. 【核心 JJJ-2】`floatEquality` 的 NaN 特判是 NaN 哨兵的**必要配套**

### 3.1 `operator==` 对 7 个 NaN 字段全部用 `floatEquality`

```cpp
// packages/react-native/ReactCommon/react/renderer/attributedstring/TextAttributes.cpp:177-183
      floatEquality(maxFontSizeMultiplier, rhs.maxFontSizeMultiplier) &&
      floatEquality(opacity, rhs.opacity) &&
      floatEquality(fontSize, rhs.fontSize) &&
      floatEquality(fontSizeMultiplier, rhs.fontSizeMultiplier) &&
      floatEquality(letterSpacing, rhs.letterSpacing) &&
      floatEquality(lineHeight, rhs.lineHeight) &&
      floatEquality(textShadowRadius, rhs.textShadowRadius);
```

### 3.2 若换成朴素的 `==`，这套设计就是坏的

**`floatEquality` 的 NaN 特判**（63 文档 §2.4）：

```cpp
// packages/react-native/ReactCommon/react/utils/FloatComparison.h:19-21
  return (std::isnan(a) && std::isnan(b)) || (!std::isnan(a) && !std::isnan(b) && std::abs(a - b) < epsilon);
```

**即 `floatEquality(NaN, NaN) == true`**。

| 若用朴素 `==` | 结果 | 后果 |
| --- | --- | --- |
| `NaN == NaN` | **false** | **两个都「未设置」的 `fontSize` 永远「不相等」** |
| → | | **每次 diff 都认为文本属性变了** → **文本测量缓存永不命中**（66 文档 FFF-1）→ **持续重排重测** |
| **与 64 文档 DDD-2 同源** | | 那里的 `+inf` 让 Yoga 布局缓存永久失效；**这里的 NaN 会让文本属性 diff 永久失配** |

**即：63 文档记录的「NaN == NaN 视为相等」不是随意的选择，而是这套 NaN 哨兵设计的必要配套。**

### 3.3 跨文档闭环

| 文档 | 结论 | 关系 |
| --- | --- | --- |
| **63 文档 §2.4** | `floatEquality` 的 `isnan(a) && isnan(b)` 分支「是有意的，但无注释」 | **本文补上「为什么有意」** —— 因为 7 个字段用 NaN 哨兵 |
| **59 文档（`ParagraphAttributesTest.cpp`）** | 测试逐字写明「operator== must special-case NaN via floatEquality so two freshly default-constructed ParagraphAttributes compare equal」 | **同一意图的第三处证据**（本文是实现侧） |
| **53 文档 §2** | Yoga 消毒**拒 NaN**、放行 `±inf` | **闭环**：NaN 在测量层被拦住，`+inf` 没有 —— **两层对非有限值的策略不一致** |

> **即：`floatEquality` 的 NaN 特判在三个独立位置被固定下来**（实现 / 测试 / 注释），
> **说明这是团队明确知晓并依赖的行为** ——
> **尽管 `FloatComparison.h` 本身一个字都没写**（63 文档 §2.4 的「无注释」结论成立）。

### 3.4 但仍有残留的不一致

| 情形 | `floatEquality` 的结果 | 是否符合「未设置」语义 |
| --- | --- | --- |
| NaN vs NaN | **true** | ✅ 符合（两个都未设置） |
| NaN vs 14.0 | **false** | ✅ 符合（一个未设置、一个有值） |
| **NaN vs NaN，但其中一个其实是「用户设了 NaN」** | **true** | ❌ **不可区分**（§2.4 的风险） |

**即：这套编码在「用户传入 NaN」时会产生歧义** ——
**但由于 53 文档证明 NaN 在测量层会被消毒掉，歧义不会传导到渲染结果**。

## 4. 【核心 JJJ-3】`AttributedStringBox` 的非法 `Mode` 有**两种**处理策略

### 4.1 `operator==` 的 `switch` **没有 `default`**

```cpp
// packages/react-native/ReactCommon/react/renderer/attributedstring/AttributedStringBox.cpp:64-76
bool operator==(
    const AttributedStringBox& lhs,
    const AttributedStringBox& rhs) {
  if (lhs.getMode() != rhs.getMode()) {
    return false;
  }

  switch (lhs.getMode()) {
    case AttributedStringBox::Mode::Value:
      return lhs.getValue() == rhs.getValue();
    case AttributedStringBox::Mode::OpaquePointer:
      return lhs.getOpaquePointer() == rhs.getOpaquePointer();
  }
}
```

**`Mode` 只有 `Value` 与 `OpaquePointer` 两个值** → **switch 穷尽** → 正常路径不会「掉落」。

**但若 `mode_` 因内存损坏而是其它值 → 函数走到 switch 末尾、**隐式返回 `false`** → **未定义行为**（返回类型是 `bool`，无 return 的路径是 UB）。

### 4.2 `std::hash` 的 `switch` **有 `default`**

```cpp
// packages/react-native/ReactCommon/react/renderer/attributedstring/AttributedStringBox.h:70-81
template <>
struct std::hash<facebook::react::AttributedStringBox> {
  size_t operator()(const facebook::react::AttributedStringBox& attributedStringBox) const
  {
    switch (attributedStringBox.getMode()) {
      case facebook::react::AttributedStringBox::Mode::Value:
        return std::hash<facebook::react::AttributedString>()(attributedStringBox.getValue());
      case facebook::react::AttributedStringBox::Mode::OpaquePointer:
        return std::hash<std::shared_ptr<void>>()(attributedStringBox.getOpaquePointer());
      default:
        react_native_assert(false && "Invalid AttributedStringBox::Mode");
        return 0;
    }
  }
};
```

**`default` 分支有 `react_native_assert(false && ...)`** → **release 下（65 文档 EEE-1）整个 assert 被编译掉，只剩 `return 0`**。

### 4.3 两种策略的对照

| | `operator==` | `std::hash` |
| --- | --- | --- |
| **有 `default`** | ❌ | ✅ |
| **非法值时的结果** | **隐式返回 `false`（UB）** | **返回 `0`（所有非法值哈希相同 → 全部落进同一桶）** |
| **可观测性** | 无 | release 下**完全静默**；dev 下有 assert |

**即：同一个类的两个「按 mode 分派」的函数，非法值处理策略不同。**

**与 65 文档 EEE-1b 的对照**：那里是「Android 仍 abort、非 Android 只打日志」的**平台不对称**；
**这里是「同一文件内两个函数」的策略不一致**。

### 4.4 前置条件检查在 release 下全部消失

```cpp
// packages/react-native/ReactCommon/react/renderer/attributedstring/AttributedStringBox.cpp:40-53
const AttributedString& AttributedStringBox::getValue() const {
  react_native_assert(mode_ == AttributedStringBox::Mode::Value);
  react_native_assert(value_);
  return *value_;
}

std::shared_ptr<void> AttributedStringBox::getOpaquePointer() const {
  react_native_assert(mode_ == AttributedStringBox::Mode::OpaquePointer);
  react_native_assert(opaquePointer_);
  return opaquePointer_;
}
```

**两处 `react_native_assert` 都是「前置条件」检查（不是数据校验）** ——
**release 下全部消失** → 若 `mode_` 与实际持有的指针不匹配，**release 下 `*value_` 解引用空指针 → 崩溃**。

### 4.5 move 赋值把 `other` 重置成「空的 Value 盒」，但 `opaquePointer_` 没重置

```cpp
// packages/react-native/ReactCommon/react/renderer/attributedstring/AttributedStringBox.cpp:54-66
AttributedStringBox& AttributedStringBox::operator=(
    AttributedStringBox&& other) noexcept {
  if (this != &other) {
    mode_ = other.mode_;
    value_ = std::move(other.value_);
    opaquePointer_ = std::move(other.opaquePointer_);
    other.mode_ = AttributedStringBox::Mode::Value;
    other.value_ = std::make_shared<const AttributedString>(AttributedString{});
  }
  return *this;
}
```

| 字段 | 移动后 `other` 的状态 | 是否自洽 |
| --- | --- | --- |
| `mode_` | `Value` | ✓ |
| `value_` | **新建的空 `AttributedString`** | ✓ |
| `opaquePointer_` | **仍持有已移空的 `shared_ptr`（非 null）** | ⚠️ **与 `mode_ = Value` 不自洽** |

**即：moved-from 对象的 `mode_` 说「我是 Value」，但它同时持有一个非空的 `opaquePointer_`**。
**若有人对 moved-from 对象调 `getOpaquePointer()`** → **dev 下 assert 失败，release 下返回一个未定义语义的指针**。

**无实际危害**（moved-from 对象按约定不应被使用），**但这是一处「重置不完整」**。

### 4.6 一个结构体持有两个 `shared_ptr`

```cpp
// packages/react-native/ReactCommon/react/renderer/attributedstring/AttributedStringBox.h:59-62
  Mode mode_;
  std::shared_ptr<const AttributedString> value_;
  std::shared_ptr<void> opaquePointer_;
```

**每个 `AttributedStringBox` 固定占 2 个 `shared_ptr`（32 字节），但同一时刻只有一个有效** ——
**另一半是纯浪费**。

**设计上可以用 `std::variant` 消除**，但 variant 也有自己的成本（对齐）。
**属「有意的取舍」，但无注释说明。**

| 项 | 状态 |

### 5.3 转换层的额外风险：`RawProps` 的类型判定

`conversions.h` 的职责是「`RawProps`（JS 传来的动态值）→ 强类型属性」的转换。
**每一处转换都要判断「这个值是什么类型」**，而**类型判断失败时应该做什么**有多种选择：
**忽略 / 抛异常 / 记日志 / 用默认值**。

**65 文档已实测**：`react_native_expect` 的语义是「非致命，只记日志」——
**即类型不匹配时**静默沿用默认值**。

| 后果 | 说明 |
| --- | --- |
| **优点** | 不会因为 JS 传了错误类型而崩溃 —— **对「不可信输入」是正确取舍** |
| **代价** | **JS 侧的错误完全静默** —— 开发者传错 prop 类型**没有任何提示**（只有 native log） |
| **与 56 文档（JS 层的 DEV 校验层）的对照** | 56 文档记录了 JS 侧有 `__DEV__` 校验；**但 C++ 侧这一层只有 log** |

## 6. 附带发现：`defaultTextAttributes()` 的跨平台差异与 `layoutDirection` 的自认 TODO

### 6.1 默认值是「非显然且跨平台可不同」的

```cpp
// packages/react-native/ReactCommon/react/renderer/attributedstring/TextAttributes.cpp:186-197
TextAttributes TextAttributes::defaultTextAttributes() {
  static auto textAttributes = [] {
    auto defaultAttrs = TextAttributes{};
    // Non-obvious (can be different among platforms) default text attributes.
    defaultAttrs.foregroundColor = blackColor();
    defaultAttrs.backgroundColor = clearColor();
    defaultAttrs.fontSize = 14.0;
    defaultAttrs.fontSizeMultiplier = 1.0;
    return defaultAttrs;
  }();
  return textAttributes;
}
```

| 特征 | 评价 |
| --- | --- |
| `static auto`（函数内 static，C++11 起线程安全的一次性初始化） | ✓ |
| `fontSize = 14.0` —— **覆盖了 NaN 哨兵** | ✓ **这是必须的**：默认字号 14 与「未设置」（NaN）必须区分 |
| 注释 `Non-obvious (can be different among platforms) default text attributes.` | ✓ **主动声明了跨平台差异** —— 但**没有说明差异在哪** |

**⚠️ 但注意**：`defaultTextAttributes()` **只覆盖了 4 个字段**（`foregroundColor` / `backgroundColor` / `fontSize` / `fontSizeMultiplier`），
**其余 3 个 NaN 哨兵字段（`opacity` / `maxFontSizeMultiplier` / `letterSpacing` / `lineHeight` / `textShadowRadius`）在默认值里仍是 NaN** ✓ **正确**（它们本就该是「未设置」）。
