# 08 · 组件注册表：Descriptor 的发现、惰性注册与回退

> **模块**：E1（`ReactCommon/react/renderer/componentregistry` 等，36 个非测试文件）
> **基线**：react-native @ `9b131e42`（submodule `react-native/`，本文路径基准 = 该 submodule 根）
> **承接**：[07 文档](./07-Fabric组件层与Props体系.md) 介绍了 `ComponentDescriptor` 的契约，本文回答「这些 Descriptor 从哪来、何时被创建」。

## 1. 两级注册表结构

组件注册不是一个平坦的表，而是**两级 + 弱引用**：

```
┌──────────────────────────────────────────────────────────────┐
│ ComponentDescriptorProviderRegistry   （进程级，全局唯一）      │
│   componentDescriptorProviders_       map<Handle, Provider>    │
│   componentDescriptorProviderRequest_  惰性请求回调             │
│   componentDescriptorRegistries_      vector<weak_ptr<Registry>>│
└────────────────────────┬─────────────────────────────────────┘
                         │ 创建（每个 Surface/实例一个）
                         ▼
┌──────────────────────────────────────────────────────────────┐
│ ComponentDescriptorRegistry   （每实例一个，持有实际对象）      │
│   _registryByHandle   map<Handle,   Shared<Descriptor>>        │
│   _registryByName     map<string,    Shared<Descriptor>>        │
│   _fallbackComponentDescriptor                                      │
└──────────────────────────────────────────────────────────────┘
```

两级之间通过**弱指针**连接（`ComponentDescriptorProviderRegistry.h:62`）：

```cpp
mutable std::vector<std::weak_ptr<const ComponentDescriptorRegistry>> componentDescriptorRegistries_;
```

源码注释说明了原因（`:23-28`）：

```cpp
/*
 * Registry of `ComponentDescriptorProvider`s (and managed
 * `ComponentDescriptorRegistry`s). The class maintains a list of
 * `ComponentDescriptorRegistry`s (retaining pointers weakly) and update them
 * accordingly to changes in the provider registry.
 */
```

**Provider 全局存活，Registry 随实例生死**。全局不能持有 Registry 的强引用，否则实例销毁后 ProviderRegistry 会一直持有已死对象。

## 2. Provider：可复制的「构造说明书」

`ComponentDescriptorProvider` 不创建任何组件，它只是一个**可拷贝的构造说明书**，包含三部分（`ComponentDescriptorProvider.h`）：

| 字段 | 作用 |
| --- | --- |
| `name` | JS 侧组件名，如 `"RCTView"` |
| `handle` | 预分配的 `ComponentHandle`（整数 ID） |
| `flavor` | 同一 Descriptor 类的多身份标记（见 07 文档 §4.2） |
| `constructor` | 工厂函数，接收 `ComponentDescriptorParameters` 返回 `Unique<ComponentDescriptor>` |

源码注释解释了「可拷贝」这一重要性质（`ComponentDescriptorProviderRegistry.cpp:25-30`）：

```cpp
if (componentDescriptorProviders_.find(provider.handle) !=
    componentDescriptorProviders_.end()) {
  // Re-registering a provider makes no sense because it's copyable: already
  // registered one is as good as any new can be.
  return;
}
```

**重复注册直接静默返回**。上面的 `assert` 被注释掉了（`:16-23`）：

```cpp
/*
// TODO: T57583139
The assert is temporarily disabled to reduce the volume of the signal.
assert(
    componentDescriptorProviders_.find(provider.handle) ==
        componentDescriptorProviders_.end() &&
    "Attempt to register an already registered ComponentDescriptorProvider.");
*/
```

**这是一个已知的、故意弱化的校验** —— 重复注册不再报错，只会静默忽略第一个。若两个模块注册同名 Provider，**谁先到谁生效，后者无声消失**。

## 3. Registry 的创建与回填

`ComponentDescriptorProviderRegistry::createComponentDescriptorRegistry`（`ComponentDescriptorProviderRegistry.cpp:66-81`）：

```cpp
ComponentDescriptorRegistry::Shared
ComponentDescriptorProviderRegistry::createComponentDescriptorRegistry(
    const ComponentDescriptorParameters& parameters) const {
  std::shared_lock lock(mutex_);

  auto registry = std::make_shared<const ComponentDescriptorRegistry>(
      parameters, *this, parameters.contextContainer);

  for (const auto& pair : componentDescriptorProviders_) {
    registry->add(pair.second);
  }

  componentDescriptorRegistries_.push_back(registry);

  return registry;
}
```

流程：**先创建空 Registry → 回填所有已注册 Provider → 记入弱引用列表**。

后续再有 Provider 注册时，会广播给所有存活的 Registry（`add`，`:34-41`）：

```cpp
for (const auto& weakRegistry : componentDescriptorRegistries_) {
  auto registry = weakRegistry.lock();
  if (!registry) {
    continue;
  }

  registry->add(provider);
}
```

`weakRegistry.lock()` 失败即跳过 —— 这就是弱引用列表能安全累积已死 Registry 的原因。

**注意**：该广播路径**不清理** `componentDescriptorRegistries_` 中的失效项，因此这个 vector 会随实例创建/销毁单调增长。属于轻微内存残留（weak_ptr 本身不持有对象）。

## 4. 惰性注册：按需请求

这是本模块最重要的机制。

`ComponentDescriptorProviderRegistry.h:38-46` 定义了请求回调：

```cpp
/*
 * ComponenDescriptorRegistry will call the `request` in case if a component
 * with given name wasn't registered yet.
 * The request handler must register a ComponentDescriptor with requested name
 * synchronously during handling the request.
 * The request can be called on any thread.
 * The methods can be called on any thread.
 */
void setComponentDescriptorProviderRequest(ComponentDescriptorProviderRequest request) const;
```

**注意约束：请求处理必须同步完成注册**。异步注册会导致下面的查找失败。

`ComponentDescriptorRegistry::at(name)`（`ComponentDescriptorRegistry.cpp:63-87`）：

```cpp
const ComponentDescriptor& ComponentDescriptorRegistry::at(
    const std::string& componentName) const {
  std::shared_lock lock(mutex_);

  auto unifiedComponentName = componentNameByReactViewName(componentName);

  auto it = _registryByName.find(unifiedComponentName);
  if (it == _registryByName.end()) {
    lock.unlock();                                    // ← 关键：先解锁
    providerRegistry_.request(unifiedComponentName.c_str());
    lock.lock();

    it = _registryByName.find(unifiedComponentName);
    ...
```

**`lock.unlock()` → `request()` → `lock.lock()`** 是这里的核心：请求回调会反过来调用 `Registry::add()`（内部取 `unique_lock`），若不先解锁就会**自死锁**。

这解释了为什么注释强调「必须在处理请求期间同步注册」—— 回调内部会走 `add()` 这条需要写锁的路径。

### 4.1 请求仍失败后的三段回退

`ComponentDescriptorRegistry.cpp:88-118`：

```cpp
if (it == _registryByName.end()) {
#ifndef RCT_REMOVE_LEGACY_COMPONENT_INTEROP
  if (ReactNativeFeatureFlags::useFabricInterop()) {
    // When interop is enabled, if the component is not found we rely on
    // UnstableLegacyViewManagerAutomaticComponentDescriptor to support legacy
    // components in new architecture.
    auto componentDescriptor = std::make_shared<
        const UnstableLegacyViewManagerAutomaticComponentDescriptor>(
        parameters_, unifiedComponentName);
    registerComponentDescriptor(componentDescriptor);
    return *_registryByName.find(unifiedComponentName)->second;
  } else {
#endif // RCT_REMOVE_LEGACY_COMPONENT_INTEROP
    // When interop is disabled, if the component is not found we rely on
    // fallbackComponentDescriptor (default:
    // UnimplementedNativeViewComponentDescriptor).
    // UnimplementedNativeViewComponentDescriptor displays a View in debug
    // mode to alert the developer that the component is not properly
    // configured, and an empty view in release mode.
    if (_fallbackComponentDescriptor == nullptr) {
      throw std::invalid_argument(
          ("Unable to find componentDescriptor for " + unifiedComponentName)
              .c_str());
    } else {
      return *_fallbackComponentDescriptor.get();
    }
```

**回退链（按顺序）**：

| 条件 | 回退对象 | 行为 |
| --- | --- | --- |
| `useFabricInterop()` 开启 | `UnstableLegacyViewManagerAutomaticComponentDescriptor` | 尝试用旧 ViewManager 支撑遗留组件 |
| fallback 已设置 | `_fallbackComponentDescriptor` | 通常是 `UnimplementedNativeViewComponentDescriptor` |
| fallback 为 null | **抛 `std::invalid_argument`** | — |

**关键设计后果**：`UnimplementedNativeView` 在 Debug 下显示一个 View 提醒开发者组件未正确配置，**Release 下是空视图**。

> 这与 [05 文档的白屏章节](./05-监控检测原理与流程.md) 直接相关：
> **一个未注册的组件在 Release 下会静默变成一个「看不见的空视图」**，
> 既不崩溃也不报警——这正是白屏难以被框架自身检出的原因之一。

## 5. `componentNameByReactViewName`：名字归一

`at()` 第一步就做名字转换（`ComponentDescriptorRegistry.cpp:67`）：

```cpp
auto unifiedComponentName = componentNameByReactViewName(componentName);
```

`componentNameByReactViewName.cpp` 负责把历史遗留的 View 名映射到统一的组件名（典型如 `RCTText` → `Text`、`RCTView` → `View`）。这是新旧架构共存期的兼容层。

## 6. 一个显式的坏接口

`ComponentDescriptorRegistry.h:44-50`：

```cpp
/*
 * This is broken. Please do not use.
 * If you requesting a ComponentDescriptor and unsure that it's there, you are
 * doing something wrong.
 */
const ComponentDescriptor *findComponentDescriptorByHandle_DO_NOT_USE_THIS_IS_BROKEN(
    ComponentHandle componentHandle) const;
```

**函数名里直接写了 `DO_NOT_USE_THIS_IS_BROKEN`**。对比同类的安全接口 `at()`（抛异常）与 `hasComponentDescriptorAt()`（返回 bool），这个返回裸指针的版本既不抛异常也不返回状态，是明确的坏设计。

源码用命名而非删除来标记，属于「已知问题但暂不清理」。

## 7. 线程安全模型

| 对象 | 锁 | 保护内容 |
| --- | --- | --- |
| `ComponentDescriptorProviderRegistry` | `mutable std::shared_mutex mutex_` | provider 表、request 回调、弱引用列表 |
| `ComponentDescriptorRegistry` | `mutable std::shared_mutex mutex_` | `_registryByHandle` / `_registryByName` / `_fallbackComponentDescriptor` |

`ComponentDescriptorRegistry.h:60-80`：

```cpp
 private:
  friend class ComponentDescriptorProviderRegistry;

  void registerComponentDescriptor(const SharedComponentDescriptor &componentDescriptor) const;

  /*
   * Creates a `ComponentDescriptor` using specified
   * `ComponentDescriptorProvider` and stored `ComponentDescriptorParameters`,
   * and then adds that to the registry.
   * To be used by `ComponentDescriptorProviderRegistry` only.
   * Thread safe.
   */
  void add(const ComponentDescriptorProvider &componentDescriptorProvider) const;

  mutable std::shared_mutex mutex_;
  mutable std::unordered_map<ComponentHandle, SharedComponentDescriptor> _registryByHandle;
  mutable std::unordered_map<std::string, SharedComponentDescriptor> _registryByName;
  ComponentDescriptor::Shared _fallbackComponentDescriptor;
  ComponentDescriptorParameters parameters_{};
  const ComponentDescriptorProviderRegistry &providerRegistry_;
  std::shared_ptr<const ContextContainer> contextContainer_;
```

注意 `mutable` 修饰的锁与 map：所有写方法都是 `const` 的（通过 `mutable` 获得写权限），这是「注册表在逻辑上只增不改，但接口为 const」的设计。

`add()` 内含两条断言（`ComponentDescriptorRegistry.cpp:44-48`）：

```cpp
react_native_assert(
    componentDescriptor->getComponentHandle() ==
    componentDescriptorProvider.handle);
react_native_assert(
    componentDescriptor->getComponentName() ==
    componentDescriptorProvider.name);
```

**Descriptor 实际身份必须与 Provider 声明一致**，否则断言失败。Release 下断言被裁剪，不一致会静默产生查不到的条目。

## 8. 本模块的设计要点

| 设计 | 收益 | 代价 / 风险 |
| --- | --- | --- |
| Provider/Registry 两级 + 弱引用 | Provider 全局复用，Registry 随实例生死 | 弱引用列表不清理，长生命周期进程中有残留 |
| 惰性注册（`request` 回调） | 避免为未使用的组件创建 Descriptor | 必须同步注册，否则回退到 UnimplementedView |
| `lock.unlock()` 后再 request | 避免回调重入 `add()` 时自死锁 | 解锁到重新加锁之间存在窗口期 |
| `Flavor` 支持同类多身份 | Descriptor 类可复用 | 已标注计划移除 |
| 三段回退 | 遗留组件可继续工作 | **Release 下未注册组件静默变空视图** |
| 重复注册静默忽略 | 幂等 | 冲突不可见（assert 已按 TODO 注释） |
