## 1. 优先级来源与调整原则

本计划的优先级来自使用者给定的**主观优先级清单**（iOS → 启动装配 → 运行时 → 错误处理 → 内存管理 → CxxPlatform → 渲染器核心 → Fabric 组件层 → TurboModule → 其它 → 构建工具链 → Android → DevTools → JNI）。

**调整原则（两条，硬性）**：

| 原则 | 说明 |
| --- | --- |
| **P1 · 前置必须提前** | 若模块 X 的实现依赖模块 Y 的抽象，则 **Y 必须先读完**。否则读 X 时无法判断「这段代码为何这样写」，只能得到事实描述而非原理 |
| **P2 · 高价值前置可提前** | 即使不是硬前置，若 Y 是理解 X 的**唯一钥匙**（如 `componentregistry` 是理解 Fabric 组件注册的钥匙），允许把 Y 提前到 X 之前，但**不得因此打乱同一批次内其它模块的相对顺序** |

**已应用的两处 P1 调整**：

| 原优先级 | 调整 | 理由 |
| --- | --- | --- |
| ① iOS 平台实现 | **保持第 1**，但把 **A2（Fabric 组件层）提前到 C1 之前** | iOS 的 `RCTViewComponentView`（21 文档）与 `RCTComponentViewProtocol` 的实现**完全建立在一组 ShadowNode/Props 抽象之上**；不先读 A2，iOS 侧只能读到「调用了什么」，读不到「为什么是这个形状」 |
| ⑦ 渲染器核心 A1 | **从第 7 提前到第 3**（仅次于 iOS 与启动装配） | A1（`ShadowNode` / `UIManager` / `MountingCoordinator` / `Scheduler`）是 **A2 / C1 / C2 / E5 / E6 / E7 的共同前置**；放在第 7 位会让后续 5 个模块都无法「读懂」 |
| ⑨ TurboModule B1 | **从第 9 提前到第 6** | B1 的 codegen 产物是 iOS/Android/JNI 三端的共同输入；B1 晚于 C1/C2 会导致平台侧读到「自动生成的代码」却不理解生成规则 |

**未被调整的部分**：iOS（①）、启动装配（②）、运行时（③）、错误处理（④）、内存管理（⑤）、CxxPlatform（⑥）、Fabric 组件层（⑧）、其它（⑩）、构建工具链（⑪）、Android（⑫）、DevTools（⑬）、JNI（⑭）**保持使用者给定的相对顺序**。

## 5. 每批次的固定闭环（不可省略）

### 步骤 1 · 读（Read）

- 遍历模块 `dirs` 下的全部非测试文件
- 优先读**入口/注册/生命周期**类，再读实现细节
- 对每个关键结论记录 `文件:行号`
- **数字必须来自工具实测**（`grepCount` / `wc -l` / 编译运行 / ASan），禁止手算
- **探查子代理的报告不可直接采信**：其 grep 常未排除 vendored 头文件与测试目录，也常给错路径

### 步骤 2 · 写（Write）

- 写入 `docs/arch/<NN>-<主题>.md`
- **撰写规范**（违反会导致审计失败）：
  1. 引用用**完整仓库相对路径**：`packages/react-native/.../Foo.cpp:123`
  2. 压缩/改写过的代码块，**必须在块内首行标注出处**
  3. 结论必须注明**适用范围**（平台 / 架构 / 编译条件）
  4. **必须在开头写 front-matter**（`id` / `title` / `topic` / `symptoms` / `platforms` /
     `architecture` / `layer` / `symbols` / `claims`）—— 检索索引完全依赖它

### 步骤 3 · 审计（Audit）—— 八项门禁

```bash
node docs/arch/audit/audit-citations.mjs   # 引用可达性，必须 0 问题
node docs/arch/audit/verify-quotes.mjs     # 代码块语义，必须 0 存疑
node docs/arch/audit/check-links.mjs       # 文档间链接，必须 0 断链
node docs/arch/audit/check-headings.mjs    # 章节编号连续
node docs/arch/audit/verify-claims.mjs     # 核心事实断言双向校验（当前 1276 条）
node docs/arch/audit/check-index.mjs       # 索引体系（front-matter / 索引漂移 / 死词条）
node docs/arch/audit/coverage.mjs          # 覆盖度
node docs/arch/audit/normalize-manifest.mjs # 重算已读/缺口
```

**八条命令退出码都必须为 0。**

### 步骤 4 · 回写（Update）

1. 更新 `audit/module-manifest.json` 的 `status` / `readFiles` / `docs` / `note`
2. 跑 `normalize-manifest.mjs` 确认缺口减少，**回写 README 的所有数字（工具实测值）**
3. **重生成索引**：`node docs/arch/audit/build-index.mjs`
4. 更新本文的批次矩阵与当前状态
5. 若过程中发现**新问题**，追加到 `06-问题清单与优化建议.md`

### `done` 的判定标准

> `done` = 目录下**全部非测试文件**都已读过，且已成文。

不是「主题写过」。这是本计划的核心纪律 —— 上一轮曾出现「8 个 done 看起来很全，实则只读了 14.4%」的错觉。
