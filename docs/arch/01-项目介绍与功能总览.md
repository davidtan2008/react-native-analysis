# 01 · 项目介绍与功能总览

> **基线**：react-native @ `9b131e42`（submodule `react-native/`，本文路径基准 = 该 submodule 根）

## 1. 项目定位

**React Native** 是 Meta（Facebook）开源的跨平台原生应用开发框架，核心命题是：**用 React 编写界面，渲染到 iOS / Android 的原生控件上**。

- 源码根：`react-native/`（本仓库的 git submodule，指向 `facebook/react-native`；本文所有 `packages/...` 路径都相对它）
- 根 `package.json`：`name = "@react-native/monorepo"`，`private: true`，`version = 1000.0.0`（monorepo 内部版本号，非发布版本）
- 实际发布包：`packages/react-native/package.json` → `name = react-native`，`version = 1000.0.0`
- License：MIT（`LICENSE`）
- 包管理器：Yarn v1（`packageManager: yarn@1.22.22`）
- 工具链版本要求：`node` 由 `debugger-frontend/package.json` 的 `engines` 推断为 `^22.13.0 || ^24.3.0 || >= 26.0.0`
- 当前主线提交：`9b131e42d12 Revert D122079801 (#58727)`

与其它跨平台方案（Flutter / 原生）的核心差异：RN **不自带渲染引擎**。它把「布局结果」交给 Yoga（`packages/react-native/ReactCommon/yoga`），把「渲染」交给各端的原生视图（UIView / android.view.View），框架自身只负责**调度、diff、挂载**三件事。

## 2. 运行时分层总览

> **交互式架构图**：[React Native 运行时分层与核心组件](./diagrams/01-runtime-layers.html)
> （在浏览器中打开；含源码引用徽标与卡片，支持导出）

RN 运行时自上而下分六层，主路径单向流动：

| 层 | 职责 | 核心载体 |
| --- | --- | --- |
| 6. 应用层 | 注册组件、启动 Surface | `AppRegistryImpl.js` / `renderApplication.js` |
| 5. React 渲染器 | reconciler、调度 | `Libraries/Renderer/implementations/ReactFabric-dev.js`（预编译，不在本仓库）（预编译） |
| 4. RN 渲染器核心 (C++) | ShadowTree、差分、挂载协调 | `UIManager` / `ShadowTree` / `MountingCoordinator` |
| 3. 运行时 (C++) | JS 线程、事件循环、定时器、错误中枢 | `ReactInstance` / `RuntimeScheduler` / `TimerManager` / `JsErrorHandler` |
| 2. JS 引擎抽象 | C++ 直连引擎，取代 JSON Bridge | `jsi::Runtime`（`ReactCommon/jsi/jsi/jsi.h:705`） |
| 1. 引擎 / 平台 | Hermes 或 JSC；iOS UIView / Android View | `HermesInstance.cpp` / `RCTMountingManager.mm` |

右侧的 `JsErrorHandler` / `ReactMarker` / `jsinspector` 是横切能力，分别对应本文档的 [04](./04-崩溃日志捕获收集处理上传.md)（错误）、[05](./05-监控检测原理与流程.md)（打点与调试）。

## 7. 当前架构成熟度（重要背景）

从源码可以清楚看出这是一个**已删除旧架构主干、正在切换到新架构**的版本：

**已删除**
- `React/CxxBridge/RCTCxxBridge.mm`（旧 Bridge 运行时）—— 目录只剩 `RCTCxxBridgeDelegate.h`、`RCTMessageThread`、`RCTCxxConvert`
- `React/Base/RCTRootView.m` —— 四个初始化方法全部退化为 `return self;`
- `ReactAndroid/.../modules/exceptions/` —— 迁移到 `modules/core/ExceptionsManagerModule.kt`
- `NativeModuleCallExceptionHandler.kt`
- `InteractionManager` —— `Libraries/Interaction/` 下只剩 `PanResponder.js`、`FrameRateLogger.js`、`NativeFrameRateLogger.js`、`TouchHistoryMath.js`；顶层 `packages/react-native/index.js:436-446` 用 `Object.defineProperty` + `invariant` 在 `__DEV__` 下显式拒绝访问，并提示改用 `requestIdleCallback`

**仍在但已空转**
- `RCTBridge` 不再持有性能记录器（`RCTPerformanceLogger` 改由 `RCTInstance` 持有，通过 `RCTBridgeProxy.performanceLogger` 注入，`RCTBridge.h:224`）
- `FrameRateLogger` 的 JS 层还在，但**原生模块已不存在**（详见 `05` 文档）

**已就位**
- `ReactInstance`（C++）+ `RCTInstance`（iOS）/ `JReactInstance`（Android）
- `JsErrorHandler`（C++ 错误中枢）
- `jsinspector-modern`（Fusebox DevTools）
- `Fabric` + `UIManager` + `ShadowTree` + `MountingCoordinator`
- `RuntimeScheduler_Modern` 事件循环

理解这一点，才能正确解读后续所有章节中「这个东西为什么这么写」。
