## 3. 【核心 UU-2】配对是有条件的：`endScroll` 有三重条件

### 3.1 三处调用点

```javascript

  _handleScrollBeginDrag: (e: ScrollEvent) => void = (e: ScrollEvent) => {
    FrameRateLogger.beginScroll(); // TODO: track all scrolls after implementing onScrollEndAnimation

```

```javascript
// packages/react-native/Libraries/Components/ScrollView/ScrollView.js:1393-1412
  _handleScrollEndDrag: (e: ScrollEvent) => void = (e: ScrollEvent) => {
    const {velocity} = e.nativeEvent;
    // - If we are animating, then this is a "drag" that is stopping the scrollview and momentum end
    //   will fire.
    // - If velocity is non-zero, then the interaction will stop when momentum scroll ends or
    //   another drag starts and ends.
    // - If we don't get velocity, better to stop the interaction twice than not stop it.
    if (
      !this._isAnimating() &&
      (!velocity || (velocity.x === 0 && velocity.y === 0))
    ) {
      FrameRateLogger.endScroll();
    }
    this.props.onScrollEndDrag && this.props.onScrollEndDrag(e);
  };
```

### 3.2 配对的三种结局

| 结局 | 条件 | 结果 |
| --- | --- | --- |
| **恰好一次 `endScroll`** | `onScrollEndDrag` 且**非动画中**且速度为 0/缺失 | ✅ 配对 |
| **两次 `endScroll`** | `onScrollEndDrag` 条件满足 **且** `onMomentumScrollEnd` 也触发 | ⚠️ **多一次**（注释第 3 条显式接受） |
| **零次 `endScroll`** | `onScrollEndDrag` 时 `_isAnimating()` 为真 → 依赖后续 `onMomentumScrollEnd` | ❌ **若 momentum 事件不来，则不配对** |

**注释第 3 条把取舍写得很清楚**：

> `- If we don't get velocity, better to stop the interaction twice than not stop it.`

**即作者明确选择了「宁可多停，不要不停」。**

**这条取舍对埋点计数器的含义**：

| 前提 | 「多停一次」的后果 |
| --- | --- |
| 原生用**引用计数** | 多减一次 → 计数变负 → 提前关闭或下溢 |
| 原生用**布尔标志** | 多减一次无害；**但「少减一次」会永久卡住** |

> **即这份取舍只有在原生用布尔标志时才安全。**
> **而本仓库无实现可查（§2.2），因此无法断定原生是哪种。**
>
> **这正是包装层头注释所说的那句话**（见 §4）。

### 3.3 `beginScroll` 侧的已知不确定性

```javascript
// packages/react-native/Libraries/Interaction/FrameRateLogger.js:19-20
 * Note that `beginScroll` may be called multiple times by `ScrollResponder` - unclear if that's a
 * bug, but the native module should be robust to that.
```

**这段注释是本模块最重要的一句**：

| 短语 | 含义 |
| --- | --- |
| `may be called multiple times` | **调用方自己也无法保证只调一次** |
| `unclear if that's a bug` | **作者不确定这是调用方的 bug 还是契约允许** |
| `the native module should be robust to that` | **把正确性责任推给原生** |

**结合 §3.2**：JS 侧既可能「多停」（显式接受），也「可能多开」（承认但未解决）。
**两侧的方向不一致，契约的不变量从未被写明。**

## 4. 头注释已经把契约写在纸上

```javascript
// packages/react-native/Libraries/Interaction/FrameRateLogger.js:6-18
/**
 * Flow API for native FrameRateLogger module. If the native module is not installed, function calls
 * are just no-ops.
 *
 * Typical behavior is that `setContext` is called when a new screen is loaded (e.g. via a
 * navigation integration), and then `beginScroll` is called by `ScrollResponder` at which point the
 * native module then begins tracking frame drops. When `ScrollResponder` calls `endScroll`, the
 * native module gathers up all it's frame drop data and reports it via an analytics pipeline for
 * analysis.
 *
 * Note that `beginScroll` may be called multiple times by `ScrollResponder` - unclear if that's a
 * bug, but the native module should be robust to that.
 *
 * In the future we may add support for tracking frame drops in other types of interactions beyond
 * scrolling.
 */
```

**逐句提取**：

| # | 句子 | 性质 |
| --- | --- | --- |
| 1 | `If the native module is not installed, function calls are just no-ops.` | **明确的无实现契约** |
| 2 | `setContext` 在新页面加载时调 | 使用约定 |
| 3 | `beginScroll` 后开始跟踪掉帧 | 行为 |
| 4 | `endScroll` 后汇总并**通过分析管线上报** | **数据流向外部** |
| 5 | `beginScroll may be called multiple times … unclear if that's a bug` | **自认不确定** |
| 6 | `In the future we may add support for … beyond scrolling` | **当前只有滚动** |

> **第 4 句是本模块对用户的实际影响**：
> 若实现存在，掉帧数据会**上报到分析管线**；
> 若不存在（本仓库情形），**数据不出本机**。
>
> **第 6 句限定了覆盖面**：当前**只测滚动掉帧**，
> 启动过程、动画、列表首屏渲染等**均无埋点**。

**另一处值得注意的拼写**：`all it's frame drop data`（`it's` 应为 `its`）。
**属原文笔误，非本文转录错误。**

## 5. 唯一的硬失败点与三处静默 no-op

### 5.1 `setGlobalOptions` 在 debug 模式下会抛

```javascript
// packages/react-native/Libraries/Interaction/FrameRateLogger.js:33-46
  setGlobalOptions: function (options: {debug?: boolean, ...}) {
    if (options.debug !== undefined) {
      invariant(
        NativeFrameRateLogger,
        'Trying to debug FrameRateLogger without the native module!',
      );
    }
    NativeFrameRateLogger?.setGlobalOptions({
      debug: !!options.debug,
    });
  },
```

**注意条件是 `options.debug !== undefined`，不是 `=== true`**：

| 传入 | 是否触发 invariant |
| --- | --- |
| `{}` | ❌ 不触发 |
| `{debug: false}` | ✅ **触发**（因为 `false !== undefined`） |
| `{debug: true}` | ✅ 触发 |

> **即「显式关闭 debug」在无原生模块时也会抛错。**
> 这大概率是**非预期**的（作者想拦的是「想在无模块时开 debug」），
> 但**行为是确定的**：任何显式传 `debug` 的调用在开源仓库里都会抛。

### 5.2 其余三处全部静默

| 方法 | 行号 | 调用形态 |
| --- | --- | --- |
| `setContext` | `:52` | `NativeFrameRateLogger?.setContext(context);` |
| `beginScroll` | `:60` | `NativeFrameRateLogger?.beginScroll();` |
| `endScroll` | `:68` | `NativeFrameRateLogger?.endScroll();` |

**四处 `?.` 中三处无条件静默、一处有条件抛错。**

## 6. `_isAnimating`：一个 16ms 的启发式判定

### 6.1 判定式全文

```javascript
// packages/react-native/Libraries/Components/ScrollView/ScrollView.js:1418-1427
  _isAnimating: () => boolean = () => {
    const now = global.performance.now();
    const timeSinceLastMomentumScrollEnd =
      now - this._lastMomentumScrollEndTime;
    const isAnimating =
      timeSinceLastMomentumScrollEnd < IS_ANIMATING_TOUCH_START_THRESHOLD_MS ||
      this._lastMomentumScrollEndTime < this._lastMomentumScrollBeginTime;
    return isAnimating;
  };
```

**阈值**（`:797`）：`const IS_ANIMATING_TOUCH_START_THRESHOLD_MS = 16;`

**两个状态字段**（`:863-864`）：`_lastMomentumScrollBeginTime: number = 0`、`_lastMomentumScrollEndTime: number = 0`

### 6.2 两个条件的语义

| # | 条件 | 含义 |
| --- | --- | --- |
| ① | `timeSinceLastMomentumScrollEnd < 16` | **刚结束惯性滚动不足 16ms** → 视为仍在动画 |
| ② | `_lastMomentumScrollEndTime < _lastMomentumScrollBeginTime` | **最近一次 begin 晚于 end** → 惯性滚动已开始但未结束 |

**初始值都是 `0`**，故组件刚挂载时：
条件② 为 `0 < 0` = **false**；条件① 为 `now - 0` 极大 → **false**。
**即初始状态判定为「不在动画」。**

### 6.3 16ms 这个数字的含义

| 参照 | 数值 |
| --- | --- |
| 本文件的阈值 | **16 ms** |
| 60fps 的一帧 | **16.67 ms** |

> **16 ms 恰好是 60fps 一帧的整数向下取整。**
> **即「距上次惯性结束不到一帧」视为仍在动画。**
>
> **在 120Hz 屏幕上（8.33ms/帧）这一阈值覆盖 2 帧，在 60Hz 上覆盖 1 帧**
> —— **阈值是按 60fps 定的，未随刷新率调整**。
>
> **与 48 文档 §6 的 `ONMOVE_EPSILON = 0.1f` 对照**：
> 那是像素空间的距离阈值，这是时间空间的时长阈值；
> **两者都是「选一个数，不随平台调整」的形态。**

### 6.4 条件②的脆弱性

**条件② 依赖两个字段的相对大小，而这两个字段只在 `:1361` 与 `:1370` 被更新**：

| 事件 | 更新 |
| --- | --- |
| `onMomentumScrollBegin` | `_lastMomentumScrollBeginTime = now`（`:1361`） |
| `onMomentumScrollEnd` | `_lastMomentumScrollEndTime = now`（`:1370`） |

**若某次滚动只有 begin 没有 end（或反之），两个字段的比较关系就会「停在」中间态。**
条件② 恰好就是用来捕捉这种「begin 了但还没 end」的，
**因此条件② 是自愈的** —— 只要 begin 发生过且 end 未发生，它就持续为真。
