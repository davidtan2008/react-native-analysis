# React Native 源码深度解析文档集

> 本目录是对当前仓库源码（`git HEAD = 9b131e42d12`，`react-native` 包 `version = 1000.0.0`，对应 0.87-dev 主线）的技术梳理。
>
> **所有结论均来自源码事实**，并标注了具体文件路径与行号。凡是源码中**不存在**的能力，文档中会明确写出「不存在」，而不是按常见认知推测。这一点在「崩溃日志上传」「白屏检测」「卡顿监控」等部分尤其重要 —— 很多业界默认 RN 自带的能力，在本仓库的 OSS 版本里其实**只是扩展点**或**已废弃的空壳**。

## 关键前提：这是「框架」而不是「应用」

本仓库是 **跨平台 UI 框架**（Meta 官方 React Native）。因此：

- 它**不包含**任何业务 App，所以不存在「崩溃日志上报到自己的 APM 服务」的代码。
- 它的职责是：**捕获**错误、**标准化**为结构化数据（`ProcessedError`）、**分发**给平台层和宿主 App（`ReactJsExceptionHandler` / `RCTHostDelegate` / `RedBoxHandler`），由 App 或第三方 APM SDK 决定**采集与上传**策略。
- 生产环境（`__DEV__ === false`）下，所有 UI 级错误展示（RedBox / LogBox）默认关闭，框架只做「上报给宿主」这一件事。

这个定位是理解后续所有章节的前提。
